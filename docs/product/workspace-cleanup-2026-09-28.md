## 보존 및 검증

- 두 Git 저장소의 추적 파일과 삭제 후보를 대조했다. 상위 저장소에 이미 추가돼 있던 Python 바이트코드 10개는 대응하는 `.py` 원본이 존재함을 확인하고 삭제했다. 두 Git 인덱스는 변경하지 않았다. 내부 앱 저장소의 코드·회귀 테스트·설정·마이그레이션은 삭제하지 않았다.
- 삭제 전 12,542개 파일의 해시를 기록했다. 삭제 후 코드·원본·업무 DB·환경 설정·두 Git 인덱스를 포함한 **1,196개 파일의 SHA-256이 일치**했다. 의도한 바이트코드 10개 삭제 외에 누락이나 변경은 없었다. 이 검증 후 본 보고서와 backlog만 작성했다.
- 현재 사용 경로인 `baselines`의 **11,336개 PNG**는 전체 파일 존재 여부와 크기가 일치했다. 이 이미지들의 삭제 후 해시 재계산은 하지 않았다.
- 모든 삭제 대상의 절대 경로가 이 작업 폴더 안에 있는지 확인했다. Web 빌드 안의 rimraf junction은 링크 자체만 제거했으며, 실제 `node_modules/rimraf`는 유지했다. 그 밖의 삭제 대상에는 링크가 없었다.
- 기존 `.runtime/api-venv`에서 FastAPI, Pydantic, PyMuPDF import가 성공했다. 현재 Next.js SWC 네이티브 바이너리의 로드와 관련 패키지 경로 해석도 성공했다.
- 애플리케이션 동작 코드를 변경하지 않아 전체 API·브라우저 회귀 테스트와 빌드를 재실행하지 않았다. 이번 확인은 파일 보존과 실행 의존성 로드 검증이며, 전체 기능에 오류가 없다는 판정은 아니다.
