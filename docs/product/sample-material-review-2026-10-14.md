원본의 37개 캐시 오류는 12개 `#DIV/0!`와 25개 `#REF!`다. 위치·원인은 [기존 진단](realytics-os-next-work-roadmap.md)에 기록되어 있다. 전체 수식의 정적 추적에서 D11/D26/D72/D74 선행경로에는 이 오류나 M207이 없었다. WORST/BEST를 정상안 복제로 복구하거나 모든 시나리오가 정상이라고 표시할 수 없다. 최초 검토는 `fullCalcOnLoad=true`인 원본 캐시였고, 후속 검토 사본에서는 실제 Excel 재계산을 별도로 확인했다.

기존 legacy importer의 메모리 실행은 `FeasibilityStudyV2` 스키마 검증과 64기간 파싱을 통과했다. 원본 validator의 `failed` 상태는 그대로 남는다. **구조화 성공·수치 검증·원본 승인은 별개**다. 월별 개별 반올림과 총액 반올림도 매출 2원·비용 1원 차이가 있어 대사 차이를 숨기지 않는다.

S4 p1–87·S6 p1–117의 native/OCR 본문을 페이지 순서대로 모두 읽었다. 별도로 204쪽 렌더를 개관하고 S4 16쪽·S6 14쪽의 주요 표·도식을 확대 대조했다. 축소 심사안건·계약·기업 재무·공문·도면·민감도 표의 모든 셀 전사는 미검증이다. OCR 숫자를 실제 입력으로 반영할 때는 해당 페이지 원본을 다시 확인한다.

27단계는 `schemas/orchestration.py::PF_REVIEW_STEPS`를 유지한다. 샘플 확인 결과는 다음 기존 단계에 전달할 수 있다.

- 1–3: 사업별 자료 구분, 용어·단위 주석, 토지 증거 검토.
- 4–10: 개발·수지·PF·수익 지표·스트레스·신용보강·상환적립 검토. 미지원 약정은 해당 계산 후보에 표시.
- 11–16: 시장 근거·상품성·자료 품질·Agent 대사·합의·법률/인허가. 원문 충돌을 합의로 삭제하지 않음.
- 17–22: 위험·보완·신용 검토·구조 조정·협의안·개발가능성. 채무 상환과 전체 사업 회수 구분.
- 23–27: 검토 보고서·근거 그래프·품질·승인 준비도·IC Memo/Term Sheet. 입력 버전과 남은 조건을 동일하게 반영.

실제 심사자료가 요구하는 보고서는 사업·관계자/거래 구조, 자금 사용·조달, 사업수지·회수, 시장·인허가, 위험·통제, 인출 선행조건·사후관리와 근거 부록을 포함한다. 현재 CF 비교 초안의 4개 섹션은 이 전체 심사보고서를 대체하지 않는다. 기존 일반 PF 보고서·최종 발행 경로와 역할을 나눠 보완한다.

일반 PF 보고서는 `schemas/report.py::PHASE_11_SECTION_ORDER`의 기존 20절을 재사용한다. 금융조건·채권보전·할인 trigger·조달·자금용도·토지·일정·구조도·상품별 납입·배분·CF·차주·시공·시장·사업성·Exit·인출조건·EOD·집행순위에 원문을 연결할 수 있다. 현재 요약 본문은 변동기준·선후취·일수계산·최초인출 만기·수수료 모수, 상품별 분할납입·조건부 적립과 완료/예정 구분을 충분히 재현하지 못한다. 새 보고서 체계보다 기존 20절의 입력·근거 연결을 보완한다.

## 실제 자료와 예제 입력의 구분

`services/api-server/data/examples/dudong_lg_logistics_pf.json`은 PF 1,000억원·선매각 1,944억원·NOI 97.2억원 등으로 S5의 개발 PF 700억원·예정 선매각 885억원·취득펀드 첫해 예상 NOI 53.63억원과 다르다. `daegu_bondong_mixed_use_pf.json`도 PF 700억원 등 S7과 다른 입력이다. 파일 경로 외에 payload 자체의 합성 예제 표지와 원문 hash·쪽수 연결은 없다.

이 예제와 회귀 테스트는 보존한다. 표시·메타데이터를 보완해 **예제 통과를 원본 실자료 검증 완료로 설명하지 않도록** 한다. 이름이 같은 원문을 근거로 기존 예제 숫자를 정답 처리하거나 원문 값으로 일괄 교체하지 않는다.

## 검토 결과의 확인

원본 8개와 기존 본리동 검토 입력 JSON의 SHA256이 유지되며, PDF 336쪽·DOCX 60개 XML 표와 34개 내장 이미지·27개 PF 단계의 개수를 다시 대조했다. 통합 문서는 자료별 담당자가 교차검토하고 금융 지표 명칭·근생 배분조건·예상 NOI의 주체·파서 경고 범위를 정정했다. 변경 문서 5개의 상대 파일 링크 156개와 공백 검사를 통과했다.

이번 검토에서 만든 렌더·OCR·추출문·스크립트 808개, 169,802,454bytes를 지정 임시폴더 안에서만 삭제했다. 원본 목록·검증 기록과 자료군별 요약 JSON 4개만 Git 제외 영역에 남겼다. 원본·기존 검토 JSON·다른 작업의 런타임·백업은 보존했다.

이번 변경은 문서 5개뿐이다. 애플리케이션 코드의 직전 검증 기준은 `a2cc2b8`의 [전체 CI 통과](https://github.com/parkwh79-stack/real-estate-os/actions/runs/38510838325)이며, 이를 이번 샘플 전수 계산 검증으로 확대하지 않는다. 원본 수식 자동 복구·데이터 승인·운영 DB 쓰기는 수행하지 않았다.
