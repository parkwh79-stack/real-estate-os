# REALYTICS 현재 구현 현황

Updated: 2026-11-04

문서와 코드의 연결을 다시 점검한 현재 기준이다. 과거의 기능별 개발 일지와 중복된 상태 설명은 [통합 이전 기록](../archive/documentation-baseline-2026-09-28.md)에 보존했다. 작업 순서는 [제품 실행 계획](realytics-os-next-work-roadmap.md) 한 곳에서 관리한다.

## 대시보드 최신 변경

2026-11-04 후속으로 프로젝트 카드, 목록과 필터에 연결된 요약 지표, 상단 유리
효과와 장식 배경 패럴랙스를 추가했다. 시작 화면에는 대시보드 이동 링크와 전송
한도 안내가 있다. [화면 기준](realytics-os-next-work-roadmap.md)

PDF 원본 보기에서 현재 페이지의 ‘글자 읽기’를 실행할 수 있다. 기존 ParserAgent가
텍스트나 로컬 OCR을 읽고 원본 페이지에 연결된 검토 결과를 저장한다.
[판독과 저장 기준](smart-intake.md)

2026-11-04 업로드 크기 오류 후속으로 작은 파일 묶음과 큰 파일의 3 MiB 분할 전송을
추가했다. 전송 크기·해시·사용자·프로젝트 범위를 검사하고 기존 원본 보관·악성 파일
검사·파서를 사용한다. API pilot 새 이미지가 Ready이며 배포 모드 업로드 회귀 26개가
통과했다. 전송 한도·임시 조각 수명·실제 검증 범위는 [Smart Intake](smart-intake.md)와
[배포 기록](deployment-plan.md)의 후속을 따른다.

2026-11-04 사용자 승인으로 최근 프로젝트·다음 행동을 중심으로 화면을 정리했다.
접힌 분석 도구/자료실, 모바일 메뉴, 계정 메뉴, 후보 선택 검색을 제공한다.
최근 작업 6개 미리보기와 확인 필요/처리 중 필터는 조회된 최근 최대 20개 기준이며,
전체 프로젝트 검색은 별도 목록을 사용한다. 조회 실패를 정상 0건으로 표시하지
않고 실행/승인을 구분하며, 실패·차단·반려·보류는 접지 않는다.
새 프로젝트 업로드는 넓은 작업 창에서 진행하고 현재 대시보드 내 닫기/재열기,
분류 실패 재시도에 파일을 유지한다. 저장 전 자료의 영구 보존은 보장하지 않는다.
기존 API·DB·Agent·Pod·계산·권한·증거 계약은 유지한다.
배포용 빌드에서 관련 PC·모바일 회귀 110개와 API 10개·공통 계약 11개가 통과했다.
웹 타입·린트·빌드 및 네 가지 화면 폭을 확인했다. 개발 서버에서만 관찰된 최초
이동 실패의 원인은 미확정이며, 실제 계정의 새 업로드 완료까지 주장하지 않는다.
로컬·배포 검증의 구체적 범위는 [변경 이력](../backlog.md)의 최신 행과 PR을 따른다.

## 최신 가입 흐름

2026-11-03 사용자 지시로 기관 신청·초대·승인을 첫 가입 경로에서 분리했다.
기존 pilot의 단순 가입 모드에서는 인증된 계정의 기본 분석 공간을 자동으로
연결하고 대시보드를 연다. 표시명·약관은 기존 가입 화면에서 처리하며 연락처·직책·
기관명·사업자번호를 추가로 입력하지 않는다. 기존 기관 신청은 보존하고 기관 관리
권한은 부여하지 않는다. 다중 기존 멤버십 선택과 비활성·철회·DB 장애 경계는 유지한다.
로그인의 legacy app_state 생성 시도도 제거했다. 실제 배포·회원 인수 범위는
[배포 기록](deployment-plan.md)의 최신 후속을 따른다.

## 판단

핵심 도구는 상당 부분 구현돼 있다. **기존 6개 Chief Pod와 업무 Agent를 유지하면서 한 프로젝트의 자료·입력·계산·검토 초안을 이어서 사용하는 경험을 완성**한다. 일관된 입력 버전과 Agent 산출물을 화면·다운로드에 반영하는 작업이 우선이다. 이번 정리에서 Agent·Pod나 27단계 PF 흐름은 삭제하지 않았다.

아래의 “코드 있음”은 현재 파일·호출 경로를 확인했다는 뜻이며, 오늘 모든 기능을 실사용 검증했다는 뜻은 아니다.

2026-10-14 사용자가 샘플 전체 검토를 먼저 지시했다. 개인전용·법인 공유공간은
현재 범위에서 제외한다. [샘플 검토 결과](sample-material-review-2026-10-14.md)는
실제 자료의 단위·계약·기준일 충돌과 코드의 의미 매핑 문제를 분리해 기록한다.
기존 예제 테스트 통과와 실제 원본 검증 완료는 구분하며, 다음 구현 순서는 실행
계획의 현재 착수점을 따른다.

후속 지시로 실제자료 수정·재계산·비교·재열기와 화면/다운로드의 동일 계산 기준을
우선 검증했다. 항목별 원본 대조·사용자 가정을 각 CF 실행에 저장해 비교와 초안에
표시하고, PDF 기준 연결·명시적 검토 상태·한글 글꼴을 보완했다. 실제 본리동 금액과
명시적 검증용 금융 가정의 격리 API 흐름은 통과했으며, 실사용자·운영 DB·실제 약정
인수와 검토된 운영 PDF 기준 등록은 별도다. Coding Worker 경합은 해당 기능의
활성화 과제로 유지하며 일반 분석을 막는 조건으로 사용하지 않는다.

추가 보완으로 토지조서 기지급과 미지급·예정액을 분리했고, 누락된 물류 입력으로
NOI·LTV·점수를 생성하던 처리를 수정했다. 입력이 부족한 지표만 미확인으로
남기며 독립적인 분석은 계속한다. 조서상 지급 기록은 실제 송금 증빙과 다르고,
기존 저장본 재가져오기·실제 계약 조건·물류 비교사례 분류 확인은 남아 있다.

2026-10-15의 4번 후속으로 본리동 원본 금리·수수료·명시적 0을 출처와 함께
가져오고 기존 검토 화면의 저장 조건과 대조하도록 연결했다. 배열수식 검사 누락과
SQLite 기동 시 불필요한 전체 이력 로딩도 보완했다. 실제 DB의 프로젝트 작업영역
읽기만 측정했으며 전체 서버 성능 인수를 뜻하지 않는다. 후속으로 주차비율 참조 3개를
복구한 검토 사본의 Excel 전체 재계산·변경/원복·재열기를 확인했다. 사본 오류는
34개가 남고 주요 수지 금액은 유지됐다. 이력은 프로젝트별 지연 조회로 바꿨고,
보고서 다운로드·시장근거 수집/검토는 단건 저장한다. 실제 DB 초기 읽기 0.5997초는
전체 API 기동 시간이 아니다. WORST/BEST·누락 면적, 토지비 차이의 이유와 본리동
실제 약정 확인은 남는다. [검증 범위와 한계](realytics-os-next-work-roadmap.md).

후속 보고서 연결로 저장된 현금흐름 계산을 직접 선택해 일반 PF 초안의 12절에
고정할 수 있다. 선택 시 입력/결과 hash를 확인하고 원본 실행·입력·결과를 저장해
재열기·JSON/PDF/Word가 같은 기준을 사용한다. 이어 사업성·PF·수익률·상환순서·
미분양 LTV·트랜치 회수 실행도 항목별로 선택해 11·16·17절에 고정한다. 미선택
항목은 미확인으로 남기며 과거 입력 미보관 기록은 선택하지 못한다. 다른 절은
생성 당시 프로젝트 자료이며, 서로 다른 선택 실행의 입력 정합성까지 검증 완료로
표시하지 않는다. 실제 본리동 원본의 사업성·예산 방식 CF도 격리 저장·재열기/JSON
일치를 검증 대상으로 포함했다. [현재 계약과 검증](realytics-os-next-work-roadmap.md).

추가로 선택 계산의 공통 예산 입력과 같은 시나리오 계열의 업무입력 대조를 보고서에
저장한다. 차이·누락·단위 확인 필요를 구분하며 재열기와 다섯 형식 다운로드에서
저장 입력과 대조 결과의 일치를 검증한다. 본리동의 총액은 일치하지만 상세 비용
4항목의 입력 미보관을 그대로 표시했다. 전체 정합성 승인을 대신하지 않으며 차이가
있는 분석 초안도 저장할 수 있다. Word는 실제 자료의 입력 대조 부록 2페이지를
Microsoft Word 출력·PNG로 확인했고 행 분리와 제목 스타일을 보완했다. 전체 20절
문서 인수와 나머지 절의 계산/근거 연결은 남아 있다.

2026-10-19 후속으로 새 초안의 자금조달·자금사용 절도 선택 CF의 저장 입력에
연결하고, 금융조건 절은 선택 PF의 트랜치 조건에 연결했다. 실행 미선택·금리 누락과
명시적 0을 구분하며 현재 프로젝트의 다른 조건으로 채우지 않는다. 절별 실행 ID와
입력 hash를 화면과 보고서에 보관하고 저장 본문을 다시 검증한다. 과거 보고서는
기존 저장본으로 열린다. 조달·매출·총사업비를 임의 합산하지 않으며 실제 집행·약정
확인을 별도로 표시한다. 일정·분양수금·금융구조 등 나머지 절의 연결과 전체 Word
문서 인수는 계속 남는다.

같은 날 추가 후속으로 8절 일정·9절 금융구조·10절 분양수금도 선택 CF의 저장
입력·결과에 연결했다. 절별 실행 ID·입력/결과 hash와 추정·미승인·누락을 보존하며
저장 본문을 재검증한다. 참여자나 실제 납입 계획을 임의로 채우지 않는다. 사용자
선택에 따라 보고서·입력 대조·CF 비교의 금액·금리·비율은 정수로 반올림 표시하고
금리·비율은 % 및 필요시 `약`을 붙인다. 계산·원본 JSON의 정밀도는 유지하며 기존
봉인된 비교 Markdown은 원문을 보존한다. 원본의 64개 기간 행은 사건 4행과 월별
60행이며 현재 계산은 49행이다. 후속 15행의 거래금액이 모두 0이어서 비용 누락은
없지만 사건·달력과 계산 월차의 대응·이자기간 검증은 남는다. 실제 본리동 전체 Word는 20절·3부록의
최종 27페이지를 모두 시각 점검했다. 문서 가독성 확인과 실제 근거·약정 승인은 구분한다.
전체 구현·검증 범위와 다음 작업은
[최신 실행 계획](realytics-os-next-work-roadmap.md)을 따른다.

가장 최근 후속에서는 본리동의 사전 사건 4개와 원본 월 번호 60개를 별도로 보관하고,
착공/준공의 원본 대응 및 계산 49행을 기간 기준에 기록했다. 날짜 없는 사건을 실제
개월로 계산하지 않으며 예산 CF·독립 PF 시나리오는 계속 제공한다. 월별 금융 재계산과
기간 스트레스만 해당 시간 근거를 요구한다. 저장·재열기·보고서 다운로드가 같은
기간 기준을 사용하며 과거 무기록 실행과 hash는 바꾸지 않는다. 최대부족 위치의
1기준 순번과 화면의 0기준 행 위치 차이도 표시 계층에서 보완했다. 기존 원본 금액과

## 바로잡은 상태 설명

- PF 기본 흐름은 `schemas/orchestration.py::PF_REVIEW_STEPS`의 **27단계**다. 과거 문서의 18단계는 이전 구현이다.
- PDF·DOCX·Excel은 “화면만 있고 내보내기는 미구현” 상태가 아니다. 생성 기능과 최종 발행 자격은 구분한다.
- 프로젝트 Cash Flow export는 `cashflow-export-completions`를 호출한다. 과거 backlog의 “callback 연결 필요”를 현재 미구현으로 다시 등록하지 않는다.
- `/api/export-cf`의 고정 값은 별도 샘플 템플릿 경로다. 실제 프로젝트 다운로드 경로와 혼합하지 않는다. 사용 중인 샘플·회귀 fixture를 무조건 삭제하지 않는다.
- 인증·PostgreSQL·비동기 실행 코드가 이미 있다. “로그인이 전혀 없음”, “모든 실행이 동기식”, “PostgreSQL 미구현” 같은 포괄적 설명은 폐기한다.
- 공공정책 Pod 이름만으로 독립된 정책 시뮬레이터가 구현됐다고 볼 수 없다. 현재 개발가능성 평가 재사용 범위를 표시한다.

## 사용자 가치에 영향을 주는 남은 연결

1. 입력 수정부터 재계산·비교·재열기까지 이어지는 작업 흐름을 실제 자료로 검증한다.
2. 분석용 사용자 가정과 확인된 증거를 함께 보여주되, 누락된 최종 승인 자료가 무관한 분석까지 막지 않게 한다.
3. 결과 화면과 다운로드가 같은 CalculationRun·입력 스냅샷을 사용하는지 확인한다.
4. PDF 비교 기준은 실행별 새 report ID와 별개로 연결해야 한다. 최초 이미지를 만든 상태는 검토된 기준과의 비교 통과가 아니다.
5. Coding Worker의 상태 경합은 해당 기능의 활성화 과제다. 일반 사업성 검토 제품을 먼저 만드는 순서를 막는 전역 조건으로 쓰지 않는다.

## 검증의 범위

[2026-09-15 코드 감사](pod-agent-code-audit-2026-09-15.md)는 해당 revision의 과거 결과다. 최신 R1/R2 변경·검증은 [backlog](../backlog.md)와 [실행 계획](realytics-os-next-work-roadmap.md)에 기록한다. Supabase migration 26개의 버전·이름과 Naver v1 배포 소스는 2026-10-14 대조 결과 일치하며 이번 변경에 새 migration은 없다. 실제 사업수지는 사용자 승인 반올림과 원본값·처리 이유를 보존해 저장·재개·기본 계산을 격리 검증했다. 원본 수식 오류와 미확인 대출 조건 때문에 전체 실자료·월별 금융 인수는 남아 있다. 운영 권한·백업·외부 배포의 완료를 뜻하지 않는다.
