# Risk Register Agent

Updated: 2026-05-25

## Purpose

Risk Register Agent consolidates risks generated by REALYTICS x PLATFORM9 agents into one credit-review table.

It does not replace domain agents. It collects their findings so Credit Review Agent and human reviewers can see one source of truth for:

- land and title risks,
- marketability and sales risks,
- legal and permit risks,
- cash-flow and Max Minus risks,
- PF structure and Exit risks,
- scenario and unsold LTV risks,
- data quality conflicts.

## Current Schema

Current schema version:

```text
realytics-risk-register-v1
```

Current output:

| Field | Description |
|---|---|
| `status` | `clear`, `watch`, `high_risk`, or `blocking` |
| `summary` | Risk counts by severity and category |
| `risks` | Consolidated risk rows |
| `topRisks` | Highest-score risks for credit review |
| `approvalConditions` | Candidate approval conditions derived from high and critical risks |
| `creditReviewInputs` | Decision-band, must-resolve issues, human-review count, and owner agents |
| `dataLimitations` | Missing source artifacts that may make the register incomplete |

## Risk Row

Each risk row includes:

| Field | Description |
|---|---|
| `riskId` | Stable register-style ID such as `R-LAND-001` |
| `sourceAgent` | Agent or engine that produced the risk |
| `sourceArtifact` | Artifact key inside the orchestration run |
| `category` | Land Risk, Market Risk, Legal Risk, Financing Risk, Exit Risk, Data Quality Risk, etc. |
| `code` | Normalized risk code |
| `title` | Short risk title |
| `description` | Issue description |
| `severity` | `critical`, `high`, `medium`, or `low` |
| `probability` | `very_high`, `high`, `medium`, `low`, or `very_low` |
| `score` | Severity x probability score |
| `grade` | Low, Moderate, High, or Critical |
| `mitigant` | Recommended mitigation or approval condition basis |
| `evidenceIds` | Evidence IDs, API evidence keys, or uploaded document evidence references |
| `sourceLocators` | Optional Excel cell, document page/table row, API record path, or agent artifact path |
| `sourceDocumentIds` | Optional archived document IDs linked to the risk |
| `evidenceGraphLinks` | Node IDs created by Evidence Graph for risk, evidence, claims, documents, and locators |
| `ownerAgent` | Agent expected to resolve or explain the risk |
| `requiresHumanReview` | Whether reviewer action is required |
| `reviewStatus` | `pending_review`, `approved`, `waived`, `needs_revision`, `resolved`, or `not_required` |
| `reviewHistory` | Reviewer, timestamp, comment, and waiver reason audit trail |
| `creditDecisionImpact` | Approval impact used by Credit Review Agent |

## Orchestration Position

Risk Register Agent runs after the Basic Risk Matrix and before Phase 11 report generation.

```text
Legal Review
  -> Basic Risk Matrix
  -> Risk Register Agent
  -> Phase 11 Report
  -> Evidence Graph
  -> Quality Gate
```

The register emits a typed `risk_register_to_credit_review` handoff so Credit Review Agent can make a decision from a structured risk table, not scattered agent messages.

## Important Rule

Risk Register Agent must not hide or collapse material risk into a vague summary. It should preserve the source agent, source artifact, code, severity, mitigation, and human-review requirement for every material issue.

## Review Workflow

Implemented review statuses:

| Status | Meaning |
|---|---|
| `approved` | Reviewer accepts the risk and mitigation as drafted |
| `waived` | Reviewer accepts approval can proceed with an explicit waiver reason |
| `needs_revision` | Upstream Agent output or risk wording must be revised |
| `resolved` | Reviewer confirms the risk has been resolved |

API:

```text
POST /projects/{project_id}/orchestrations/{run_id}/risk-register/{risk_id}/review
```

Final orchestration approval is blocked while material risks that require human review remain outside `approved`, `waived`, or `resolved`.

## Evidence Graph Linkage

Risk rows are now first-class Evidence Graph nodes.

For each risk row, Evidence Graph creates:

- `risk:{riskId}` node,
- links to `artifact:{sourceArtifact}`,
- links to `evidence:{evidenceId}` nodes,
- links to `source:{archiveId}` nodes when source document IDs are available,
- links to `locator:{riskId}:{locatorId}` nodes for Excel cells, document locators, API record paths, or agent artifact paths,
- links to claim nodes derived from the same source artifact.

This is required for internal credit review, audit response, and later similar-case database learning. A material risk should not be treated as audit-grade unless it has at least an agent artifact link and, preferably, explicit evidence IDs or source locators.
